When I first posted about osury eight months ago, it did one thing: turn an OpenAPI spec into ReScript types with Sury schemas.

osury 2.10 is out, and it has become a small compiler: one spec, one intermediate representation, four targets.

🟦 ReScript + Sury — records and variants with runtime schemas, genType for TypeScript
🟨 Effect TS — Effect Schema v4
🟧 OCaml — plain types with yojson codecs, no ppx
🟩 Rust — serde structs and enums

The most useful thing in this release came from an uncomfortable audit.

Every target had a golden test: a spec covering every construct, compared byte for byte. All green. But only the ReScript output was ever compiled. When I ran the other goldens through their own toolchains:

→ Rust: a recursive type with "infinite size" — the golden had been pinning code that doesn't build
→ Effect TS: a schema referencing itself before it exists — the module crashed on import
→ Mutual recursion (A → B → A) worked in none of the four targets
→ A discriminated union used the schema name as its tag instead of the value on the wire — in all four at once, because the bug lived in the shared IR

A snapshot test tells you the output changed. It never tells you the output is right.

So now every target, under every flag combination, must build with its own compiler (rescript, ocamlfind, cargo, tsc --strict) and decode sample data generated from the same spec. That check also caught an enum value "open" that ReScript only accepts as #"open".

Also new:
• --exact-optional: "key absent" and "value null" stay distinct, so a PATCH body can say leave it / clear it / set it
• Errors carry a JSON path, a typed kind and a fix hint
• MIT license file, finally

And a new home: osury.coreofkeen.com. The examples there are generated in your browser by the same code the CLI runs, and the playground takes your own spec.

npm i -D osury

If you maintain a code generator with snapshot tests, compile your snapshots. At least once.

Thanks again to Dmitry Zakharov for Sury, which this all started from.

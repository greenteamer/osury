## RU

**osury 2.10: один OpenAPI — четыре языка, и теперь каждый из них реально компилируется**

osury начинался как узкий инструмент: OpenAPI → ReScript-типы со схемами Sury.
За последние месяцы он вырос в компилятор с общим IR и четырьмя бэкендами —
ReScript, Effect TS, OCaml, Rust. В 2.10 я сел проверить, насколько эти четыре
таргета на самом деле равноправны. Ответ оказался неприятным — и полезным.

**Что выяснилось.** У каждого таргета был golden-файл: синтетическая спека,
покрывающая все конструкции, и побайтовое сравнение вывода. Зелёные тесты,
спокойная жизнь. Но компилировался из четырёх только ReScript. Стоило прогнать
остальные golden'ы через их собственные тулчейны:

- Rust: `pub parent: Option<Node>` — `recursive type has infinite size`. Golden
  месяцами фиксировал код, который не собирается.
- Effect TS: `Schema.Array(Node)` внутри определения `Node` — модуль падает при
  импорте.
- Взаимная рекурсия (A→B→A) не работала **ни в одном** из четырёх, включая
  «основной» ReScript.
- Union на уровне поля с `discriminator` без `mapping` получал тегом имя схемы
  (`"IssueLoop"`), хотя на проводе — `"loop_found"`. Во всех таргетах сразу:
  баг жил в общем IR.

Golden-тест отвечает на вопрос «изменился ли вывод?». На вопрос «правильный ли
он?» он не отвечает вообще — он с одинаковым усердием охраняет и корректный код,
и сломанный.

**Что теперь.** Новый тест паритета: одна и та же спека × 4 комбинации флагов ×
каждый таргет. Сгенерированный код обязан (1) собраться родным компилятором —
`rescript`, `ocamlfind`, `cargo`, `tsc --strict` — и (2) декодировать sample-данные,
построенные из той же спеки. Второе условие поймало ещё и баги в самом генераторе
примеров: он не знал про wire-кодировки и мог положить `null` в обязательное поле.

Рекурсию каждый язык разрывает по-своему, и это теперь данные в IR, а не
случайность печати: `type rec … and …` в ReScript/OCaml, `Box<T>` в Rust (но не
внутри `Vec` — он и так в куче), `Schema.suspend` плюс выписанные руками
`X`/`XEncoded` в Effect TS, потому что тип нельзя вывести из самого себя.

**Ещё в релизе:**

- `--exact-optional`: поле «не required + nullable» имеет три состояния — значение,
  `null`, ключа нет. Для PATCH это три разные команды: не трогать / очистить /
  установить. Под флагом: `option<Nullable.t<t>>`, `t option option`,
  `Option<Option<T>>` (с хелпером — голый serde читает оба как `None`),
  `optionalKey(NullOr(t))`.
- Документ без единой схемы — теперь ошибка с подсказкой, а не «✓ Generated 0
  types» с кодом 0.
- Demo-площадка снова жива. Она не собиралась с версии 0.29: сменился суффикс
  скомпилированных файлов, а demo жил со своим самописным TS-принтером и ничего
  об этом не знал. Теперь demo вызывает те же генераторы, что и CLI, показывает
  все четыре языка, а `npm test` падает, если он снова отстанет.

**Проверка на бою:** на двух продакшен-спеках вывод ReScript и Rust побайтно
совпал с 2.9.0; OCaml отличается только аннотациями типов; Effect TS — только тем
единственным рекурсивным типом, который раньше был сломан. 282 теста.

Главный вывод не про osury. Если у вас кодогенератор с несколькими таргетами и
snapshot-тестами — скомпилируйте снапшоты. Хотя бы один раз.

`npm i -D osury` · demo: osury-production.up.railway.app

## EN

**osury 2.10: one OpenAPI spec, four languages — and now each of them actually compiles**

osury started as a narrow tool: OpenAPI → ReScript types with Sury schemas. It
has since grown into a small compiler with a shared IR and four backends —
ReScript, Effect TS, OCaml, Rust. For 2.10 I audited how equal those four really
are. The answer was unpleasant, and useful.

Every target had a golden file: a synthetic spec covering every construct,
compared byte for byte. Green tests. But only the ReScript output was ever
*compiled*. Running the other goldens through their own toolchains found:

- Rust: `pub parent: Option<Node>` — `recursive type has infinite size`. The
  golden had been pinning code that does not build.
- Effect TS: `Schema.Array(Node)` inside `Node`'s own initializer — the module
  crashes on import.
- Mutual recursion (A→B→A) worked in **none** of the four, ReScript included.
- A field-level union with `discriminator` but no `mapping` was tagged with the
  schema name (`"IssueLoop"`) while the wire says `"loop_found"` — in all four
  targets at once, because the bug lived in the shared IR.

A golden test answers "did the output change?". It says nothing about "is the
output right?" — it guards broken code as faithfully as correct code.

So there is now a parity test: same spec × 4 flag combinations × every target.
The generated code must (1) build with the target's own compiler — `rescript`,
`ocamlfind`, `cargo`, `tsc --strict` — and (2) decode sample data derived from
the same spec. The second condition also caught bugs in the sample generator.

Each language breaks a reference cycle its own way, and that is now data in the
IR rather than an accident of printing: `type rec … and …`, `Box<T>` (but not
inside a `Vec`), `Schema.suspend` plus hand-written `X`/`XEncoded` interfaces.

Also in this release: `--exact-optional` (absent ≠ null — three states for PATCH
bodies, expressed natively in each target), a structured error instead of
"✓ Generated 0 types" for an input with no schemas, and a rebuilt playground
that calls the very generators the CLI does and shows all four targets.

On two production specs the ReScript and Rust output is byte-identical to 2.9.0.
282 tests.

The takeaway is not about osury: if you maintain a multi-target code generator
with snapshot tests — compile your snapshots. At least once.
